# 教訓集

## 社長の好みと決まり（最重要）
- **報告は必ず日本語**。英語で報告して叱られたことがある。進み具合のひとことも日本語で書く。
- **言われる前に考えて足す**。「私の指示に頼らず自立して思考して構築して」と言われている。
  - 例：所持品・所持金・財産・住まい・相続・パーティーは、言われる前に作るべきだった。
- 世界の**常識とバランス**を大事にする。
  - 町に動物が多すぎる、町にスライムがいる、といった状態は不可。
- **全ての生き物が考えて暮らす**。全員に役割と目的を持たせる。
- 見た目はすべて違うものにする。4方向に歩き、正面（下向き）も描く。
- 会社組織で動く（eldeland-org スキル）。知識はすべてスキルに記録し、コミット・プッシュする。
- **承認制**：部長が考えた案は、実行する前に社長に報告して許可を得る。許可された案だけを社員に命令する。

## 社長の要望の履歴（何を求められてきたか）
1. 見下ろし型のドット絵3D。角度は自由に変えられる。API 不要。住人は記憶と性格を持ち、自分を人間だと思っている。
2. 広大な大陸にする。町・村・城・城下町・ダンジョン・ピラミッド・港・牧場・砂漠・ジャングル・季節・魔王・戦争・国・研究・監獄を入れる。7つの欲求、ショートスリーパーとロングスリーパー、殺人・結婚・家畜。
3. 扉で人がチカチカする不具合を直す。吹き出しを重ねない。台詞を重複させない。
4. 生き物の見た目を個体ごとに変え、4方向に歩かせる。職業と役職を最大限に増やす。
5. アイテム、素材、武器、防具、道具を入れる。ギルド、依頼、経済を入れる。全建物とダンジョンの内装をクリックで見られるようにする。危険を察知する力と、魔物の分布図を持たせる。町を守る兵士を置く。
6. 所持金、財産、住まい、冒険者パーティーを入れる。
7. 会社組織の体制で進める。知識はスキルに記録する。
9. 国の税金について質問があった。当時の税は、世帯から一律に取るだけの簡素な仕組みだった。
10. ゲームは基本無料で公開し、広告で収益を得る方向を社長が検討している。収益を専門に考える収益部を作った。
11. 案A〜Kは許可された。案L（収益化の第1段階）は保留。公開先は Cloudflare Pages。収益の議論が本格化したら宣伝部を作る。
8. 部長が社長の代わりに考え、案は一度社長に報告する。許可したものだけを部下に命令して実行する。

## 過去の不具合と直し方
| 症状 | 原因 | 直し方 |
|---|---|---|
| 歴史の生成が終わらない | 職業の枠を埋めるループが、農夫を農夫に割り当て直していた | 候補から `p.job===job` を除く |
| 道の経路探索が遅い | 毎回 heap.sort していた | MinHeap にする |
| 城が置けない・家が足りない | 区画設計が甘かった | 格子状の通り、城の予約区画、tryPlace、扉から道まで舗装、半径の拡大 |
| 建物の id がずれる | addBuilding の id に別の数を使っていた | `buildings.length` を id にする |
| 扉でチカチカする | 同じ建物内で行動が変わるたびに、いったん外に出ていた | startAction で同じ建物への移動は外に出さない |
| 暴力が多すぎて人口が減る | 喧嘩がすべて殺し合いになっていた | 殴り合いは致命傷にしない、盗賊退治は正当な討伐、守る役は戦士職だけ、襲撃に間隔を空ける、出生率を上げる、移住を足す |
| 懸賞金が膨らみ続ける | 上限がなかった | 上限300、強盗に間隔を空ける |
| ドラゴンが町を荒らし続ける | 名前付きの個体も襲撃に出ていた | 名前付きは襲撃しないで巣に帰る |
| 町に野生動物やスライムがいる | 町に入れる種を制限していなかった | townMask と allowedInTown。生成時に置けなければ生成しない |
| 「いらっしゃるですのよ」「好きよ（男）」「ぜ（女）」 | 語尾の組み合わせが雑だった | 身分と性別ごとの語尾表を正しくする |
| ギルドのランキングで「眠っ中」 | 「ている」を「中」に機械的に置き換えていた | 短い表示でも元の文を切り詰めるだけにする |
| 好みの欄が「鍛錬し、work」 | ラベル文から語尾を削っていた。work のラベルがなかった | 名詞形の PREF_LABEL を別に持つ |
| 形見が「竜の鱗」 | 素材まで形見の候補に入れていた | 形見は素材以外から選ぶ |
| 冒険者が世界で6人しかいない | 王都の職業枠が各1人だった | 流れの冒険者の到来（宿住まい）と、若者が冒険者を志す仕組みを足した |
| 「〇〇家が〇〇家から家を買い取った」 | 大家と借り手が同じ苗字（親戚）だった | 個人名（フルネーム）で書く |
| 畑の持ち主が0件 | world.fields がタイル単位で、村によってはほとんど無い | 畑は世帯ごとの区画数 hh.land として抽象化した |

## バランスの目安
- 人口は開始時に約380〜420人。30日で ±10% 以内が健全。
- 家計の平均は約130〜160銅貨。財布の平均は約20銅貨。
- 家の値打ち：`w*d*40` に、王都は×1.6、港は×1.2、村は×0.8 を掛ける。週の家賃は値打ち÷28。3週滞納で追い出す（情け深い大家は1回だけ待つ）。
- 宿代は1人1日3銅貨。
- 襲撃は6〜10日おき。巣からの襲撃は8日の間隔を空ける。
- 研究の速さは ×0.3。
- 性能：node で1日約7〜8秒、ブラウザで1分あたり約3.4ms。

## 作業上の注意
- Playwright は `/opt/node22/lib/node_modules/playwright/index.mjs` を絶対パスで import する。`playwright install` はしない。
- テストで `sim.pushLog` をラップすると、S.log（400件で打ち切り）より多くのログを取れる。
- 記憶の本文は `m.txt`（`m.text` ではない）。
- 停止フックが未コミットの変更を検出するので、区切りごとにコミット・プッシュする。
