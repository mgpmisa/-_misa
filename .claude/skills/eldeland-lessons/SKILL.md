# 教訓集

## 社長の好みと決まり（最重要）
- **報告は必ず日本語**。英語で報告して叱られたことがある。進み具合のひとことも日本語で書く。
- **言われる前に考えて足す**。「私の指示に頼らず自立して思考して構築して」と言われている。
  - 例：所持品・所持金・財産・住まい・相続・パーティーは、言われる前に作るべきだった。
- 世界の**常識とバランス**を大事にする。
  - 町に動物が多すぎる、町にスライムがいる、といった状態は不可。
- **全ての生き物が考えて暮らす**。全員に役割と目的を持たせる。
- 見た目はすべて違うものにする。4方向に歩き、正面（下向き）も描く。
- 会社組織で動く（eldeland-org スキル）。知識はすべてスキルに記録し、コミット・プッシュする。
- **承認制**：部長が考えた案は、実行する前に社長に報告して許可を得る。許可された案だけを社員に命令する。

## 社長の要望の履歴（何を求められてきたか）
1. 見下ろし型のドット絵3D。角度は自由に変えられる。API 不要。住人は記憶と性格を持ち、自分を人間だと思っている。
2. 広大な大陸にする。町・村・城・城下町・ダンジョン・ピラミッド・港・牧場・砂漠・ジャングル・季節・魔王・戦争・国・研究・監獄を入れる。7つの欲求、ショートスリーパーとロングスリーパー、殺人・結婚・家畜。
3. 扉で人がチカチカする不具合を直す。吹き出しを重ねない。台詞を重複させない。
4. 生き物の見た目を個体ごとに変え、4方向に歩かせる。職業と役職を最大限に増やす。
5. アイテム、素材、武器、防具、道具を入れる。ギルド、依頼、経済を入れる。全建物とダンジョンの内装をクリックで見られるようにする。危険を察知する力と、魔物の分布図を持たせる。町を守る兵士を置く。
6. 所持金、財産、住まい、冒険者パーティーを入れる。
7. 会社組織の体制で進める。知識はスキルに記録する。
9. 国の税金について質問があった。当時の税は、世帯から一律に取るだけの簡素な仕組みだった。
10. ゲームは基本無料で公開し、広告で収益を得る方向を社長が検討している。収益を専門に考える収益部を作った。
11. 案A〜Kは許可された。案L（収益化の第1段階）は保留。公開先は Cloudflare Pages。収益の議論が本格化したら宣伝部を作る。
12. あらゆる犯罪者（性犯罪・薬物・異常者など）の導入を指示された。部長方針は次のとおり（社長に報告済み）。
   - 性犯罪は抽象表現のみで、描写はしない。当事者は18歳以上に限る。
   - 「異常者」は、心の病ではなく、共感を欠いた猟奇犯として描く（偏見を避けるため）。
   - 重い犯罪はメニューの S.settings.matureCrimes で切り替えられるようにする（公開・広告審査への備え）。
13. 生物のあらゆるアニメーション（会話・攻撃・仕事・死亡・瀕死・被ダメージなど）を、すべての生物に作るよう指示された。グラフィック部を2名体制にした。
   - 人の担当は js/anim_people.js、動物・魔物の担当は js/anim_creatures.js を作る。
   - sprites.js は編集せず読むだけにする。同じ個体なら、歩行とアニメーションで見た目をそろえる。
14. 地図の見直しを指示された（道・門・駐屯地）。職業の追加（開拓者・土木・御者・行商人・旅芸人）、道の整備、学び舎（学校・魔法学園・道場）も求められた。
   - 地図の担当社員に world.js・data.js・history.js・render.js（建物の部分）・interior.js の編集を任せた。
15. 会話の記録：人をクリックすると、誰と何を話したかが見られるようにした（p.talkLog は最新20件、死者は5件）。
16. 経験値と能力の成長（歩けば体力、剣で戦えば剣術、回復魔法で回復力が伸びる）を指示された。担当は js/growth.js。
17. 世界の仕組みを詳しく調べる「調査部」を作った。成果物は docs/世界の仕組み事典.md。
18. 動物・魔物にも、名前・家族・住処・飢え・序列・種族語・賢い戦い方・敗北からの学習・恨みによる報復を持たせるよう指示された。担当は monsters.js と fauna.js。
19. 世界を約10倍に広げるよう指示された。開拓済みは今の広さ、ほかは未開拓とし、国が税収で開拓して土地と資源を奪い合い、戦争もする。技術部を新設した。
20. 食物連鎖の釣り合いを指示された。どの種も絶滅させない。数の目安は、固定の数ではなく広さあたりの密度で持つ。
21. 強い魔物は駆逐しないと国を広げられない。奥地には国に属さない民族の村があり、強大な魔物に周期的に生贄を捧げて村を守る風習などの歴史を持つ。物語を作るよう指示され、物語部を作った。
   - 生贄は抽象的に描き、子どもは対象にしない。
22. 経済の見直しを指示され、経済部を作った。指示の中身は次のとおり。
   - すべての物に使い道を持たせる。資源は有限、宝箱は復活させる。
   - 希少さで値段が決まるようにし、無駄な生産はしない。
   - 守り手の待遇を良くする。武器と防具に耐久値を入れる。
   - お金を7つの欲求に使う。王が休日を決め、重税だとストライキが起きる。
   - 老後の備え（年金にあたるもの）を用意する。
23. お金の流れに必ず導線（出どころと行き先）を付けるよう指示された。湧く箇所は原因を突き止めて直す。
24. 昔の世界のお金の循環について質問があり、銀行を作るよう提案された。
   - 部長の説明：金銀は鉱山から造幣所へ行って硬貨になり、造幣益は王のものになる。王の支出で世に出て、税で戻る。すり減り・退蔵・流出で減る。悪鋳をすれば物価が上がる。両替商と銀行家は、預金・貸付・為替手形を扱った。
   - 造幣所と銀行は js/bank.js、読み物は docs/お金の歴史.md。
25. 生き物の行動に意味を持たせるよう指示された。一人ひとりが目的を持って考えて生きるので、決まりきった行動をする者はいないはず。担当は js/purpose.js（人生の目的・計画・今日の心づもり・行動の理由）。
8. 部長が社長の代わりに考え、案は一度社長に報告する。許可したものだけを部下に命令して実行する。

## 過去の不具合と直し方
| 症状 | 原因 | 直し方 |
|---|---|---|
| 歴史の生成が終わらない | 職業の枠を埋めるループが、農夫を農夫に割り当て直していた | 候補から `p.job===job` を除く |
| 道の経路探索が遅い | 毎回 heap.sort していた | MinHeap にする |
| 城が置けない・家が足りない | 区画設計が甘かった | 格子状の通り、城の予約区画、tryPlace、扉から道まで舗装、半径の拡大 |
| 建物の id がずれる | addBuilding の id に別の数を使っていた | `buildings.length` を id にする |
| 扉でチカチカする | 同じ建物内で行動が変わるたびに、いったん外に出ていた | startAction で同じ建物への移動は外に出さない |
| 暴力が多すぎて人口が減る | 喧嘩がすべて殺し合いになっていた | 殴り合いは致命傷にしない、盗賊退治は正当な討伐、守る役は戦士職だけ、襲撃に間隔を空ける、出生率を上げる、移住を足す |
| 懸賞金が膨らみ続ける | 上限がなかった | 上限300、強盗に間隔を空ける |
| ドラゴンが町を荒らし続ける | 名前付きの個体も襲撃に出ていた | 名前付きは襲撃しないで巣に帰る |
| 町に野生動物やスライムがいる | 町に入れる種を制限していなかった | townMask と allowedInTown。生成時に置けなければ生成しない |
| 「いらっしゃるですのよ」「好きよ（男）」「ぜ（女）」 | 語尾の組み合わせが雑だった | 身分と性別ごとの語尾表を正しくする |
| ギルドのランキングで「眠っ中」 | 「ている」を「中」に機械的に置き換えていた | 短い表示でも元の文を切り詰めるだけにする |
| 好みの欄が「鍛錬し、work」 | ラベル文から語尾を削っていた。work のラベルがなかった | 名詞形の PREF_LABEL を別に持つ |
| 形見が「竜の鱗」 | 素材まで形見の候補に入れていた | 形見は素材以外から選ぶ |
| 冒険者が世界で6人しかいない | 王都の職業枠が各1人だった | 流れの冒険者の到来（宿住まい）と、若者が冒険者を志す仕組みを足した |
| 「〇〇家が〇〇家から家を買い取った」 | 大家と借り手が同じ苗字（親戚）だった | 個人名（フルネーム）で書く |
| 王都に門がなく外へ出られない（全12本の街道が長さ0） | 街道の A* に閉じた集合がなく、上限まで同じマスを調べ直していた | 閉じた集合を足した。城壁の東西南北には必ず門を開ける。古いセーブは load で openGates |
| 門を開けたら処理が約4倍重くなった | 遠出が増え、A* の探索が長くなった | 遠い目的地ほどヒューリスティックの重みを大きくする（1.05/1.3/1.6）。閉じた集合を足す。たどり着けない目的地は2時間キャッシュする |
| 自警団がドラゴンに挑んで全滅した | 力の差を判断していなかった | 守り手の力の合計が相手の1.1倍未満なら迎え撃たない。警鐘を鳴らして家に籠もる。格上の相手には町の中を固める |
| 赤ちゃん・囚人・貴族の飢え死に | 牢に食事がない。0〜5歳が自分で物乞いをする。夜は食べ物を買えない | 牢では1日2回の配給。6歳未満は家の蓄えから食べさせる。夜は宿屋で食事を買える。蓄えの買い足しは1人4食分を目安にする |
| お金が町の蓄えに吸い上げられる | 税が毎日5%で、使い道が施しだけだった | 税は週1回にする。蓄えが400を超えたら、貧しい人を町の普請に雇って給金を払う。豊かな町から貧しい村へ援助する |
| 引き受けた依頼が永遠に終わらない | 期限が掲示中の依頼にしかなかった | 担い手が全滅するか、引き受けから12日で打ち切り、掲示板に戻す |
| 13歳の将軍 | 年の差だけで職業を割り当てていた | 要職は21歳以上に限る。17歳未満は見習いでもできる仕事だけにする |
| 性能測定が不安定 | 社員が多数の試験を同時に回し、CPU の負荷が24（4コア）になった | 測定の値は参考にとどめる。社員には試験を1本ずつ回すよう指示する |
| 農夫が村の中心（広場の石畳）で働く | 畑がほとんど作られず（種12345で0マス）、畑の行き先が見つからないときは広場に行っていた | 森を切り開いた畑と町はずれの畑を足した（0→約170マス）。civicPlace で必ず本物の畑へ行かせる |
| 道探しが多くの経路を見つけられない | 距離を Float32Array に入れていて、丸めの誤差で同じマスを何度も積み直していた | Float64Array と閉じた集合を使う |
| 橋が描かれず、道が川で切れて見えた | 描画に橋がなかった | 橋に板と欄干を付けた |
| 詰所が門からの細い通路をふさぎ、町が分断された | 建物を置くとき、周りの通り道を確かめていなかった | keepsConnected で通り道が残るか確かめてから置く |
| 配列の外を読んだ | ハッシュ関数の結果が負になっていた | 整数のハッシュには必ず >>> 0 を付ける |
| 職業の割り当てが偏る | 枠を上から順に埋めていた | どの職も1人目 → 2人目の順に、欠かせない職から埋める |
| 死んだ支援者の needs を読んで止まった | 死者は needs などを消されている | 他人の needs に触る前に、生きているかと needs があるかを確かめる |
| オオカミが海や川の上、ゴブリンが柵の上にいて動けない | 群れの仲間を、長の周り±1マスに歩けるか確かめずに置いていた | makeCreature の最後に settleCreature で、いちばん近い立てる場所へ移す。毎時 unstick で人と生き物を見回る |
| 畑の持ち主が0件 | world.fields がタイル単位で、村によってはほとんど無い | 畑は世帯ごとの区画数 hh.land として抽象化した |

## バランスの目安
- 人口は開始時に約380〜420人。30日で ±10% 以内が健全。
- 家計の平均は約130〜160銅貨。財布の平均は約20銅貨。
- 家の値打ち：`w*d*40` に、王都は×1.6、港は×1.2、村は×0.8 を掛ける。週の家賃は値打ち÷28。3週滞納で追い出す（情け深い大家は1回だけ待つ）。
- 宿代は1人1日3銅貨。
- 襲撃は6〜10日おき。巣からの襲撃は8日の間隔を空ける。
- 研究の速さは ×0.3。
- 性能：node で1日約7〜8秒、ブラウザで1分あたり約3.4ms。

## 作業上の注意
- Playwright は `/opt/node22/lib/node_modules/playwright/index.mjs` を絶対パスで import する。`playwright install` はしない。
- テストで `sim.pushLog` をラップすると、S.log（400件で打ち切り）より多くのログを取れる。
- 記憶の本文は `m.txt`（`m.text` ではない）。
- 停止フックが未コミットの変更を検出するので、区切りごとにコミット・プッシュする。

## お金の流れの教訓（社長の指摘）
- 「市場の金庫から払っているので総額は保たれている」だけでは不十分。社長が求めるのは、人と人との取り引きの流れ。漁師が釣っている最中にお金が入る作りは、社長から見れば「湧いている」のと同じ。
- お金を足す処理を書くときは、必ず次の3つを答えられるようにする：誰が払うか、何と引き換えか、いつ（売ったとき、給料日）か。
- 点検には、毎日の総額（audit.mjs）と、関数ごとの増減（lines3.mjs：お金の置き場所に見張りを付け、呼び出した関数ごとに合計する）を使う。

## お金の作り直しで分かったこと（経済部）
- 丸め（Math.round）・上限（Math.min）・上書き（= 0）の行は、額がずれる元になる。丸めた分や切り捨てた分は、必ず誰かに渡す。
- 作り手の蔵にたまった品は腐る。腐る品を売りに出す判断を入れないと、食べ物が消えて飢えが出る。
- 帳簿（js/ledger.js）は毎日世界のお金を数え、外との出入りを除いたずれを記録する。新しいお金の置き場所を作ったら、ledger.js の合計に必ず足す。
- 市場で買うのは marketBuy、品を出すのは marketDeliver、作った品は stash、給金は accrueWage / owe（payday.js）。在庫を直接減らして代金を払わない書き方は禁止。
- 試験用の http.server の番号がほかの社員の古いサーバーとぶつかると、古いファイルを読み込んで変更が映っていないように見える。空いている番号で `--directory` を付けて起こす。
- 建物の中で「寝台が足りない」問題は、人数に見合う寝台と、身分・持ち主の順の割り当ての両方がそろって初めて直る（城で王と王妃が床に寝ていた件）。
- 職人がくじ引きで作り物を選ぶと、暮らしに要る品（釘など）が作られない。「注文」と「よく要る品を先に作る」仕組みが要る。
- 牧場や囲いには、広さに見合う数の上限を付ける（1マスあたり大きな家畜1.25頭）。
- 記憶の文を切り貼りして会話を作ると崩れやすい。「〜が」で切る・見出しを途中で切る・どんな文にも付く口癖は避ける。
- 冒険者が竜に殺される｜依頼のないときの行き先選びに、ダンジョンの危険の見極めがなかった。仲間はリーダーをまねるだけだった｜js/deadly.js に「手に負えない相手の縄張り」の決まりを1か所にまとめ、行動の候補・行き先選び・ギルド・パーティの引き止め・道探し・救助をそろえる。
- 空腹の人が急に増えた（種12345で3日目41人）｜①獣や魔物が見えているあいだ、逃げている人が毎分「見つけた」扱いになって一歩も動けず、動かないクマの近くで十数人が飢えていた（danger.js spotThreats）。②井戸のない王都が37マス先の川まで水汲みに通っていた（chores.js）。③飢えで体力が落ちると「逃げたい」が食事に勝ち続け、家に食べ物があっても食べなかった（needs.js）｜すでに逃げている人は走り続ける。水は町から r+5 マス以内の川、なければ広場の水場。逃げ込む家で食べる。※世界の生成は乱数の使い方が少し変わるだけで別の世界になる（種が同じでも、コミットの前後で人口634と680）。1つの種だけで良し悪しを決めず、種3つで比べる。
- 帳簿のずれ（1日に約10銅貨）｜市場で盗むと、盗んだお金がどこからともなく湧いていた（society.js crimeArrive）｜商人の売上箱から盗む。空ならパンだけ。
